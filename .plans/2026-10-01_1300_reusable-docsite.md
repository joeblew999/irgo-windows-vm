# A reusable docs site generator for any project with a docs/ folder

Status: proposed → agent GG · 2026-10-01

## Symptom
site/ renders this repo's docs well (goldmark + anchor + toc + chroma highlighting + GitHub alerts,
sidebar contents, llms.txt, per-page .md, sitemap, link/anchor tests, screenshots). But it cannot be
used elsewhere: the page list and nav are hard-coded in site/main.go, the repo URL and site base
default to this project, it imports this repo's `wire`, and two pages are generated by running this
repo's binary (command reference, MCP) and one from `wire/openapi`.

Versions (1 Oct): goldmark v1.8.6, chroma v2.27.0, goldmark/anchor v0.2.0, goldmark/toc v0.12.0 —
all latest. goldmark-highlighting/v2 is yuin's official extension but its last commit is 2023.

## Change
- A standalone module and command, `docsite` (go install-able; start as a module in this repo,
  move to its own repo joeblew999/docsite once stable): `docsite build|serve|check` over a docs
  folder.
- Config (docsite.toml or similar, optional): site name, repo URL, base URL, page order + nav
  labels + parents, which files are "intent" pages, generated pages as hooks (a command whose
  stdout is markdown, or an OpenAPI file to render). No config = discover README.md + docs/*.md,
  nav from H1s.
- Keep every guarantee as built-in checks: local links, anchors, links to the site from source code
  (configurable globs), screenshots referenced, llms.txt/llms-full.txt, per-page markdown, sitemap.
- Highlighting: replace goldmark-highlighting with a maintained path (a small chroma renderer of
  our own, or a maintained extension) if that removes the stale dependency without losing CSS
  classes and dark/light themes.
- This repo becomes the first consumer: docsite.toml + hooks for `irgo-winvm help`/`mcp -list`/
  the OpenAPI file; site/ shrinks to config + hooks; the pages workflow calls docsite.
- OpenAPI: the owner is finishing an OpenAPI system in another repo; design the OpenAPI page as a
  hook so it can switch to that system.

## Verify
This repo's site builds byte-for-byte equivalent content (diff the rendered pages) with all tests
green; a second, minimal project (a temp dir with README + docs/a.md, b.md) builds with no config;
docsite check catches a broken link and a broken anchor (negative controls).
