# VM capacity: disk, memory and how many VMs we allow

Status: done on its branch (agent DD) · 2026-10-01; the Worker change needs a deploy

## Symptom
Devs and agents (local, other repos, remote via the Worker) can now create VMs in 23 s. Nothing
budgets the Mac's disk or memory as a whole: this Mac has 40 GiB free of 460 GiB (91 % used);
irgo-win11 ≈ 25 GB, the golden image 10.1 GB, install media 9.1 GB, runtime screenshots 239 MB and
growing without limit, golden pulls ~19 GB on disk; clone growth over a day is unmeasured
(`cloneHeadroomBytes` = 10 GiB is a guess); each VM takes 8 GiB RAM on a 16 GiB Mac.

## Relation to other plans
Agent Z (shared Mac) adds leases, `vm-reap` and a per-vm-create RAM/disk guard. This plan is the
whole-system policy on top: measured numbers, a capacity model, limits per owner, retention of
everything the tool writes, and visibility in CLI, MCP and the Worker (ledger AA, remote jobs CC).

## Change
1. Measure: clone growth (fresh, after glaze-check, after a day of app-create), golden pull peak
   disk, shots/logs/jobs/staging growth per run. Record in RESULTS.md.
2. Capacity model in one place (internal/utmvm): disk and RAM per VM kind (owner VM, clone, golden,
   pull), reserved free space for macOS, max concurrent running VMs from RAM, max existing clones
   from disk. `irgo-winvm capacity` (CLI + MCP): what is used, by whom (leases), what is free, how
   many more VMs fit; `doctor` shows the summary.
3. Policy: vm-create / remote jobs refuse with a clear reason when over limits (three-way, cannot
   tell → refuse); per-owner quotas (count, disk) with defaults; oldest stale clones reaped first
   when space is short (only Z's reap rules: never irgo-win11 or the golden image; dry run unless
   configured to auto-reap).
4. Retention: runtime shots, logs, job records, staging, golden-pull parts, old media — bounded by
   age/size with a `prune` (dry run unless -force), run automatically within limits.
5. Worker: the Mac reports capacity snapshots to the ledger; the dashboard shows each machine's
   disk/RAM and VM counts; remote job admission (CC) checks capacity before queueing on a Mac.

## Verify
Unit tests with fakes (thresholds, cannot-tell, quotas, prune selection) + negative controls; live:
capacity numbers match df/du; a vm-create over quota is refused; prune frees the expected bytes.

## Design (as built, 1 Oct 2026)

**Measured** (RESULTS.md, "VM capacity"): one clone, `cap1`, APFS private bytes
sampled every 30 s: 0.03 GiB booted, 0.10 after `glaze-check -windows`, 0.26
after 20 `app-create`s, flat at 0.28 for 90 idle minutes; deleting it freed
0.29 GiB of `df`. `getattrlist(ATTR_CMNEXT_PRIVATESIZE)` works on a known path
in UTM's container; `st_blocks`/`du` count the golden image once per clone, and
`golden-export` (10 GB to `du`) holds 0 bytes of its own. The clone id does not
group a family, so shared blocks are counted once as the largest any file
shares. Not measured: a Windows cumulative update on a clone; per-run growth of
jobs and staging (both bounded in code).

**One model** (`internal/utmvm/capacity_model.go`), the shared-Mac guard
extended rather than duplicated: its constants moved there; `cloneReserveBytes`
4 GiB replaces the 10 GiB guess; every VM holds max(private, reserve) and is
*promised* held − private; disk test = new reserve + Σ promised + 10 GiB macOS
reserve; memory test unchanged (4 GiB reserve, 8 GiB per VM). Quota per owner
from VM records: 2 VMs, 16 GiB held (`IRGO_WINVM_QUOTA_VMS`,
`IRGO_WINVM_QUOTA_GIB`; 0 = no limit; unparsable refuses). Every unknown (a VM
disk that cannot be measured, an unreadable record, a bad quota variable) is
cannot tell, exit 7.

**Commands:** `capacity` (CLI, MCP, `-json`): volume, memory, per-VM own and
promised bytes, owners, tool data with bounds, and the guard's own verdict for
a new clone plus how many fit; `doctor` has a one-line summary. `prune` (dry
run unless `-force`): shots 14 d / 200 MiB (newest per stage kept), glaze logs
30 d / 100 MiB, staged binaries unused 7 d, `.parts`, staging and media scratch
left 1 d, each under its lock taken without waiting, each checked gone.
`vm-create` prunes on the way in; with `IRGO_WINVM_AUTO_REAP=<lease>` it runs
`vm-reap -force` when refused and asks once more. `vm-delete` now reports the
private size it frees (it reported "—").

**Worker:** a `capacity` ledger event (compact JSON in `detail`) after
`capacity`, `vm-create`, `vm-delete`, `vm-reap` and `prune -force`, only when
the ledger is on; the view keeps each machine's newest (unreadable is cannot
tell) and the page shows a Capacity table. No new endpoint, so the only thing
for the Worker API route table (FF) is the event type `capacity`. Remote jobs:
admission is `BeginCreate` for jobs that make a VM and `Capacity().Room.Clone`
otherwise; no code is added until that work lands.

**Live:** quota refusal (`IRGO_WINVM_QUOTA_GIB=1`, `-overcommit`): exit 7, no
VM, no record. First `prune -force`: 32 shots, 103 MB, matching `du`.
