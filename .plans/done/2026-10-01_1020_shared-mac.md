# Sharing one Mac between many agents and repos

Status: done on branch worktree-agent-adbde39746cf0f6ed, merge pending (agent Z) · 2026-10-01

## Symptom
Agents from other repos will use irgo-winvm on the same Mac. Everyone defaults to `irgo-win11`; each
VM takes 8 GiB on a 16 GiB Mac; `app-delete` wipes every caller's staged uploads; delete commands
treat "could not ask UTM" as "nothing to delete".

## Change
- VM ownership + leases (owner, created, last-used); `status`/`doctor` show them; `vm-reap`
  (dry run unless -force; never irgo-win11 or the golden image).
- `irgo-win11` reserved for the owner; other callers get "make your own VM (23 s)".
- Resource guard on vm-create (RAM/disk; cannot tell → refuse).
- Per-VM staging; delete commands distinguish "no such VM" from "could not ask".

## Verify
Unit tests with negative controls; live with one disposable clone at a time.

## Result
docs/DEVELOPMENT.md "Sharing one Mac" is the description; RESULTS.md "Several callers on one Mac"
the live run (one disposable clone, z1, made with -overcommit because irgo-win11 was running,
then reaped). Staging is per caller (bin/<caller>/), not per VM: app-upload does not know the VM.

## Left
- Clone growth over a day is still unmeasured (cloneHeadroomBytes 10 GiB) — plan DD, item 1.
- Two boots of existing stopped VMs at once are not counted against each other (only creates of
  new VMs record a pending pid); the window is the boot's first seconds.
- The identity is a label, not authentication; over HTTP every session shares the server's repo.
- vm-reap runs only when someone runs it; automatic reaping belongs to plan DD's policy.
