# Roadmap

What is meant to happen next. Unlike every other page here, this one is intent,
not record, and it will be wrong in the ordinary way plans are wrong.

- What has been measured: [Results](RESULTS.md).
- What was found in glaze, native and UTM: [Upstream](UPSTREAM.md).

## Next: run the long job end to end

**This is the only unverified claim in the system.** `vm-create -install` takes
about 45 minutes and returns a job handle immediately. The mechanism is proven:
a detached job survived its client exiting. The *duration* is not: the job
driven end to end finished in under a second, because the media it asked for
already existed.

To close it:

1. Run `vm-create -install` over MCP against a **disposable VM name**.
2. Disconnect the client.
3. Confirm `status` still reports the job alive minutes later.
4. Let it finish, then `app-create` a probe into the new VM.

**Cost and risk:** about 45 minutes of wall clock. `vm-create` no longer restarts UTM
(since 30 Sep 2026 UTM imports the bundle), so `irgo-win11` can keep running. Whoever owns the machine decides when this runs.

**What it catches that nothing else can:**

- a job whose output stops being written partway;
- a `status` that drifts over an hour;
- a guest agent gap mid-install;
- whether a detached process really survives an hour, not just a second.

Remote access doesn't depend on this. The HTTP server was originally gated on
"phase A works and has run against a disposable VM". Phase A has now run against
a real VM, and nothing in remote access depends on the 45-minute duration.

## Known gaps

Smaller, and known. None blocks the next step.

- **Durable suspend.** Resume takes 400 ms, but the state lives in memory, so it
  doesn't survive quitting UTM. The blocker is the emulated NVMe device, and
  NVMe is required: Windows ARM64 Setup has no inbox VirtIO storage driver. The
  way past it is to switch the system disk to VirtIO and inject the driver into
  `boot.wim`, which is now within reach because `iso-create` already drives
  wimlib over the media.
- **`Delete` safety.** It removes files up to 30 seconds after asking QEMU to
  stop, whether or not QEMU actually stopped. (`Prune` was the worse half of
  this and is fixed: it used to delete any `*.img`/`*.dmg` in the system temp
  directory, whoever owned it.)
- **Dead code.** `SchemaConfigurationVersion` and `IfaceVirtIO` are still
  unreferenced (checked 30 Sep 2026). `BuildFATImage`, `OpenDisplay`,
  `BootAssist` and `GuestToolsInstallCommand` were on this list and have since
  been removed; the last carried a `start`-wildcard bug already fixed in the
  answer file.
- **Upstream reporting.** The status of every finding is the table at the top of
  [UPSTREAM.md](UPSTREAM.md). A count kept here would be a second copy, and
  one was already wrong. As of 13 Aug 2026, nothing had been reported upstream,
  and patches for two findings existed only as uncommitted edits in local
  clones.
- **x64 under emulation** has never been measured. See
  [Results](RESULTS.md#still-to-measure-x64-under-emulation).
- **A recycled process id** could report a stranger's process as a job.
  Accepted, and documented where the check lives, in `job.alive`. Storing the
  start time and comparing it would close this if it ever matters.
- **Typed schemas cover flags, not positional arguments.** `args` is still a
  list of strings for paths and directories. That is the right shape, but a
  named property would help an agent more.

**No Irgo integration until this works standalone with glaze.** Integrating a
tool that doesn't work yet makes the framework absorb its failures.

## Done, and what proved it

Everything the plan files tracked is done, and measured in [Results](RESULTS.md).

### Run it for real — 14 Aug 2026, `075fdd5`

A real client spawned the real binary against the VM on this machine:

- nine tools listed;
- `doctor` returned **as a result**, which proves `utmvm.Capture` works where a
  unit test could not;
- `vm-screen` returned a 4,447,777-byte PNG of a live Windows desktop, and it
  was **looked at**;
- `iso-create -fetch` detached and survived the client exiting;
- `app-create` ran a probe on windows/arm64: 5 capabilities OK, 3 missing
  upstream.

`mise run app:test` re-ran green.

### Typed schemas — v0.4.0, `cd4d203`

The `FlagSet` is the source, and the schema is generated from it with
`VisitAll`. The CLI and the schema can't disagree, because there is one
registration and both read it; no test has to compare two lists.

- 8 commands, 18 flags hoisted.
- `reference.md` was byte-identical before and after, checked after the first
  command and again after the remaining seven.
- Verified against the real VM with a client passing `{"vm":"irgo-win11"}` as a
  typed property.

### The documentation resource — `c155a99`

`irgo-winvm://reference` holds every command, flag, default and the outcome
table, generated from the same `FlagSet`s the command line parses. Verified
against the real binary: one resource, 4,126 bytes.

Embedding `llms-full.txt` instead was checked and is impossible:

- `go:embed` needs the file at compile time, and it is generated into the
  gitignored `site/dist`, so a fresh clone wouldn't build.
- Committing it makes a second copy that goes stale.
- A placeholder overwritten at release means a development build silently
  serves an empty document.
- Fetching it from the site makes an offline server useless.

So the binary serves what it knows and names the URL for the rest.

### Job pruning — `1419a18`

- Twenty finished jobs are kept; older ones are pruned, logs with their records.
- Running jobs are never touched, however many there are.
- `doctor` reports the size.

Before this, `jobs/` grew a record and a log per run forever: a disk leak in a
tool that already asks for 33 GB, and a break from the rule that every action
owes an undo.

### The threat model — `9ae77ce`

Written before the port existed, as the plan required. It names what an
authenticated caller gets, what is defended and how, and what is deliberately
not defended. It recommends no inbound listener at all. See the
[threat model](THREAT-MODEL.md).

### The loopback server — `ac16122`

`irgo-winvm mcp -http 127.0.0.1:8129` serves the tools over Streamable HTTP:

- `Stateless: true`;
- cross-origin protection in middleware;
- a 10 s read-header timeout;
- DNS-rebinding protection left on;
- any non-loopback address refused outright.

At this commit `checkLoopback` also refused a bare `:port` rather than silently
rewriting it. `136a3e5` replaced that (below).

Proven by `internal/mcpserver/http_test.go`: the refusal cases, the refusal
message, refusing before listening, and an HTTP round trip.

### The wider bind and authentication — 15 Aug 2026, `136a3e5`

- `-allow-remote` consents to a non-loopback bind.
- `IRGO_WINVM_TOKEN` is the bearer token behind it, compared in constant time
  through the SDK's `auth.RequireBearerToken`.
- A bare `:port` now resolves to loopback.
- Off loopback, both consent and token are mandatory. A server that would start
  unauthenticated because the token is missing is refused outright.

Proven by `internal/mcpserver/http_test.go`: 401 without the token, 405 with
it, and the SDK's own HTTP client round-tripping a tool call with the token.

### Content-addressed, chunked uploads — 15 Aug 2026, `136a3e5`

- `app-upload` stages a binary as `bin/<sha256>.exe` from base64 chunks.
- The full SHA-256 is verified before the committed file exists; a mismatch is
  removed.
- An unchanged binary transfers nothing.
- `app-delete` clears the stage.

Proven by `internal/utmvm/app_upload_test.go`: commit and byte equality,
mismatch rejection, truncation never commits, idempotent retry, and clearing
twice. Run against a real guest on 16 Aug 2026 ([Results](RESULTS.md)).

### The mutation lock — 15 Aug 2026, `136a3e5`

One mutation at a time, refused rather than queued:

- a flock on `mutation.lock`, taken in `runTool` for every mutating command,
  including the detached job child, with a probe before forking;
- a lock whose state can't be read refuses;
- exit code 6 (`busy`, retryable) is the refusal.

Proven by `internal/utmvm/lock_test.go`, including the cross-process case.

## Notes for whoever works on the HTTP transport

`StreamableHTTPOptions` in `mcp/streamable.go` at SDK v1.7.0, read rather than
assumed. Reading it corrected two earlier instructions:

| field | what it means here |
|---|---|
| **`Stateless bool`** | **Exists.** Server-to-client requests are rejected outright, and GET/DELETE return 405. So a job handle must be keyed by an argument, not a connection, which is how it is built |
| **`DisableLocalhostProtection`** | DNS-rebinding protection is **already on by default**: a localhost request with a non-localhost `Host` is rejected with 403. Don't build this; just don't switch it off while debugging a confusing 403 |
| **`CrossOriginProtection`** | **Deprecated.** Cross-origin protection goes in middleware, `http.NewCrossOriginProtection()` wrapping the handler, not in this field |
| `MaxRequestBodyBytes` | Configurable, default 4 MiB. A negative value disables the limit entirely: never do that on an exposed server |
| `JSONResponse` | Plain JSON instead of SSE; worth having for a simple client |
| `SessionTimeout` | At the zero value, idle sessions never close |

The `MCPGODEBUG` setting `allowsessionsinstateless=1` restores session handling
in stateless mode. Needing an escape hatch is a design signal. Don't ship one.

## How to work on this

- After each commit: `mise run go:check`, `mise run go:lint` and
  `go -C site test ./...`. After each push: `mise run ci:watch`.
- Give every new gate a negative control (break it, watch it go red, put it
  back), and name the control in the commit message.
- Prove the long job by running it and quoting what happened. Never claim it.
- Change the generated pages with the behaviour. If [MCP](mcp.html) still
  describes a limitation that has been fixed, it is lying.

## Out of scope

- **Rewriting git history** to remove two compiled binaries (24 MB) that were
  once tracked. They are gone from the tree. One blob each against a 102 MB
  `.git` doesn't justify invalidating published tags and every clone.
- **A second list of anything**, for any reason.

## Why the docs test skips this page

`cmd/irgo-winvm/docs_test.go` fails if a document names an
`` `irgo-winvm <command>` `` the binary doesn't have. A roadmap names things
that don't exist yet, so this page (like the threat model) is exempt by name,
in `intentDocs`. The same sentence in any other document is refused.
